Project / Overview

Project Overview

Intaliq is a mobile fitness app that promotes outdoor running, cycling and hiking in Saudi Arabia. Users log activities, set goals, find partners and join coach-led group sessions; coaches create and manage those sessions. The project started in SE311 (Software Requirements) and SE365 (Human-Computer Interaction), which produced an approved SRS and an evaluated high-fidelity prototype. In SE322 we design and document the software architecture for the next version.

SEC_02

Problem & Solution

Problem Statement

People who want to exercise outdoors struggle to find suitable partners, stay motivated, and join organized, professionally led sessions. Most fitness apps only track individual workouts, and in Saudi Arabia coach-led communities are rare and exclusive: you usually only hear about sessions if you already know a coach. Without a shared platform, outdoor activity stays harder to start and harder to sustain.

Proposed Solution

A standalone iOS/Android app that puts activity tracking, goals, partner connections, coach-managed group sessions, announcements and an AI fitness chatbox in one place. The app talks over HTTPS to a cloud backend for data and authentication, and uses external services for AI recommendations, push notifications, email and, later, maps.

System Purpose

Make outdoor fitness more accessible, motivating and social, supporting the Vision 2030 goal of wider participation in sport. Measurable targets from the SRS include 99% availability, results within 3 seconds, and core tasks such as booking a session done in only a few steps.

SEC_06

Functional Requirements

FR-01 Book a session: a user browses group sessions, reviews session and coach details, and submits a join request; the coach accepts or rejects it and the user is notified. Full sessions cannot be requested.
FR-02 AI chatbox: a user can ask the AI chatbox for fitness advice; it refuses requests for medical advice.
FR-03 Activity goal: a user can enter an activity goal (activity type and target), which the system validates and saves.
FR-04 Connect with partners: a user can browse suggested partners by location, goals or activities and send a request; an accepted request opens a chat.
FR-05 Create group session: a coach can create a session with activity type, date, time, location, capacity and intensity level.
FR-06 Admit session members: a coach reviews pending requests and accepts or rejects them; the system enforces capacity and fitness-level match and notifies the user.
FR-07 Session announcements: a coach can publish announcements (time or location changes, reminders) that are delivered to all session members.

Source: Intaliq SRS §3 (System Features)

SEC_07

Non-Functional Requirements

NFR-01 Performance: results return within 3 seconds (PER-1), user statistics load within 4 seconds (PER-2), and app-server responses stay under 5 seconds (CI-6).
NFR-02 Availability: the system is available at least 99% of the time (REL-1) and handles many simultaneous users (AVA-1); unsent actions are stored locally offline and synced later (CI-5).
NFR-03 Security: personal data is protected from unauthorized access (SEC-1), passwords are strong (SEC-2), authentication is required before personal data is sent (CI-7), and all traffic uses HTTPS (CI-1).
NFR-04 Usability: essential tasks take only a few steps (CO-3), partner search uses filters (USE-1), and fitness statistics are clear (USE-2).
NFR-05 Localization: the interface supports Arabic and English (CO-1, UI-1), selectable measurement systems (LOC-1) and time zones (LOC-2).
NFR-06 Safety: recommendations respect health conditions and fitness level (SAF-1), and unsafe exercises show warnings (SAF-2).
