/ARCHITECTURE /LOGICAL VIEW

The Logical View describes what Intaliq does for users and coaches. It breaks the system into the domain abstractions from the SRS data dictionary (users, coaches, sessions, goals, activities and partners) and the relationships behind booking, admission, goal tracking and partner matching.

Stakeholders: Analysts, Designers Concern: Functionality

Key Abstractions

User «Entity»

A registered participant. Holds contact and login details; name lengths, Saudi (+966 5X-XXX-XXXX) or international phone format, email and password strength are validated.

- firstName: String - lastName: String - phoneNumber: String - email: String - password: String
Coach «Entity»

A fitness coach who creates and manages group sessions. Has the same identity data and validation rules as User.

- firstName: String - lastName: String - phoneNumber: String - email: String - password: String
Session «Entity»

An outdoor group session created by a coach. Date must be DD/MM/YYYY and realistic, time is 24-hour, location must be in Saudi Arabia, capacity must be more than 1.

- date: String - time: String - location: String - capacity: int - intensity: Beginner | Intermediate | Advanced
Goal «Entity»

A personal target set by a user for one of the three supported activities. Deadline cannot be in the past, and calories must be more than 10 kcal.

- type: Hiking | Biking | Running - targetTime: HH:MM - caloriesBurnt: String - deadline: String
Activity «Entity»

A logged workout. Duration must be at least 5 minutes and no more than a day.

- type: Hiking | Biking | Running - duration: String
Partner «Entity»

A suggested fitness partner, matched by location, goals and activities, that a user can send a connection request to.

- location: String - goals: String - activities: String

Attributes and constraints: Intaliq SRS §4.2 Data Dictionary
