Quality Attributes

These quality attributes come from the Intaliq SRS (§2.4, §5 and §6) and the high-fidelity prototype usability evaluation. They describe how the system must behave for users and coaches on mobile networks in Saudi Arabia. Each one is written as a scenario with a source, stimulus, environment, artifact, response and measurable target.

Selected Quality Attributes

Performance

ID: QA-01

WHY_IT_MATTERS: Users check sessions, stats and goals throughout the day. The SRS requires results within 3 seconds (PER-1), statistics within 4 seconds (PER-2), and app-server responses under 5 seconds (CI-6). If it feels slow, users lose motivation.

Quality Attribute Scenario

Source
End user (participant)
Stimulus
Requests the list of available group sessions
Environment
Normal operation over Wi-Fi or 4G/5G
Artifact
Mobile app, backend API and cloud database
Response
Sessions are fetched and shown with details (coach, time, location, capacity, intensity)
Response Measure
Results shown in ≤ 3 s; statistics in ≤ 4 s

Availability

ID: QA-02

WHY_IT_MATTERS: Coaches rely on Intaliq to fill sessions and send announcements, and users rely on it to log workouts outdoors where the connection can drop. The SRS requires at least 99% availability (REL-1), support for many simultaneous users (AVA-1), and local storage of unsent actions while offline (CI-5).

Quality Attribute Scenario

Source
End user logging an activity outdoors
Stimulus
Mobile connection is lost while the action is submitted
Environment
Degraded network: offline or intermittent coverage
Artifact
Mobile app local store and sync component
Response
The action is saved locally and synced automatically when the connection returns (CI-4, CI-5)
Response Measure
99% uptime; 0 lost activity logs after reconnect

Security

ID: QA-03

WHY_IT_MATTERS: Intaliq stores personal details, locations and activity history. The SRS requires protecting personal data from unauthorized access (SEC-1), strong passwords (SEC-2), authentication before any personal data is sent (CI-7), HTTPS (CI-1), and email verification with two-factor authentication (SI-3, CI-3).

Quality Attribute Scenario

Source
Unauthenticated or unauthorized client
Stimulus
Attempts to read another user's profile, session data or activity records
Environment
Normal operation, public internet
Artifact
Authentication service and backend data access
Response
Request is rejected; data is only returned to authenticated, authorized users over HTTPS
Response Measure
100% of personal-data requests authenticated; 0 unauthorized reads

Usability

ID: QA-04

WHY_IT_MATTERS: Intaliq serves beginners and experienced athletes in Arabic and English, so essential tasks must take only a few steps (CO-3, USE-1, USE-2). The prototype evaluation praised the clean layout and bottom navigation but found missing pop-up feedback, inconsistent back buttons, and an AI chatbox and help button that did not work yet.

Quality Attribute Scenario

Source
First-time user or coach
Stimulus
Books a session (or creates one) from the Home screen
Environment
Normal operation, Arabic or English interface
Artifact
Mobile UI: navigation, forms, confirmation and error pop-ups
Response
Task completes through the bottom navigation with clear confirmation or error messages next to the related field (UI-8)
Response Measure
Booking in a few steps (CO-3; proposed: ≤ 4 taps); feedback shown for every action
